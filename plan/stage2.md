# 阶段 2：接口、重载与错误处理

本阶段对应总计划中的“阶段 2：接口、重载与错误处理”（第 4–5 天）。从阶段 1 的命令行笔记程序继续：保留内存存储和 `add / list / show / delete / help / quit`，整理接口、输入校验和错误反馈，并为笔记提供语义清楚的比较或格式化操作。

预计用时：两天，每天约 45–90 分钟。目标不是增加大量功能，而是让现有功能的接口更明确、失败情形更好处理。

## 阶段目标

完成后应能：

- 通过函数重载提供同一概念的不同调用方式，并能说明重载解析依据。
- 在合适的接口中使用 `std::string_view`，理解它是非拥有视图及其生命周期要求。
- 知道 `std::span` 适合表达连续元素的非拥有视图，并在一个小接口中试用；不适合的地方不强行使用。
- 为 `Note` 增加有意义的相等比较或输出格式化操作。
- 区分“没有找到”这类正常结果、“用户输入无效”这类可恢复错误，以及程序无法正常继续的异常情况。
- 保持项目依赖 C++20；不把 C++23 的 `std::expected` 当作必需功能。

## 继续使用的命令

```text
add       新增一条笔记
list      列出所有笔记
show ID   按 ID 查看
delete ID 按 ID 删除
help      显示帮助
quit      退出
```

本阶段可以扩展 `show` 或存储层的查找接口，但不必增加持久化、标签、全文搜索或复杂命令框架。输入仍通过终端交互；标题和正文允许包含空格。

## 第一天：接口形状、重载与非拥有视图

### 1. 记录现有接口的契约

阅读 `NoteStore` 现有接口，为每个操作写出调用者能依赖的行为：

| 操作 | 成功时 | 未找到 / 输入无效时 |
|---|---|---|
| 新增 | 返回新 ID | 标题或正文校验失败时不新增，并向用户说明原因 |
| 按 ID 查找 | 得到笔记值或只读借用 | 得到空结果 |
| 删除 | 报告删除成功 | 返回失败状态，不改变集合 |
| 列出 | 只读遍历所有笔记 | 空集合时显示空状态 |

注意 `find_by_id()` 当前返回 `std::optional<Note>`，成功时产生笔记副本；如果之后改成 `const Note*`，它就是借用，必须说明失效边界。两种设计都可以，重点是接口语义与实现一致。

### 2. 练习函数重载

为同一概念提供两个调用方式，例如按 ID 或按标题查找：

```cpp
std::optional<Note> find(long id) const;
std::optional<Note> find(std::string_view title) const;
```

标题查找可先定义为精确匹配并返回首个匹配结果；若之后允许重名并需要返回所有匹配项，再在 STL 阶段调整接口。调用端分别尝试传整数和字符串，观察编译器选择哪个重载。

复习函数重载规则：函数名相同但参数列表不同可以构成重载；只靠返回类型不同不能重载。不要增加仅为凑练习而存在、含义难以区分的重载。

### 3. 在只读文本接口中试用 `std::string_view`

标题匹配或格式化等只读接口可以接受 `std::string_view`：

```cpp
bool title_matches(const Note& note, std::string_view query);
```

它不拥有字符，不负责释放内存。调用时传入的字符串必须在视图使用期间保持有效；不要把指向短命局部字符串的 view 存到 `NoteStore` 中，也不要把它作为长期保存标题的类型。`Note::title` 继续使用拥有字符串的 `std::string`。

### 4. 了解 `std::span` 的适用场景

`std::span<const Note>` 可以把一段连续的 `Note` 序列作为只读参数传给函数，而不复制元素或接管所有权。可选练习是写一个只接收 span 的汇总/展示函数，并从 `NoteStore::all()` 传入 vector。

`span` 本身不拥有元素，底层容器销毁或发生使元素地址失效的修改后，不能继续使用它。当前项目若没有需要接受不同连续容器的函数，可以只做独立小练习，不必为了使用 `span` 改造核心接口。

### 当天验证

- 按 ID 和按标题调用对应重载，确认标题含空格也能匹配。
- 标题不存在时得到明确的空结果，而不是崩溃。
- 如果试写 span 汇总函数，分别用空集合和非空集合调用。
- 能解释 `std::string`、`std::string_view`、`std::span` 的所有权差异。

## 第二天：比较、格式化与错误策略

### 1. 为 `Note` 增加有意义的比较或格式化操作

二选一即可，也可以都练习：

- **相等比较：** 定义两个 `Note` 在什么意义上相等。可用 C++20 默认比较运算符 `bool operator==(const Note&) const = default;` 表达所有成员逐一相等；也可以明确规定只比较 ID。文档或注释应说明采用的语义，避免调用者误以为是另一种。
- **流输出：** 定义 `std::ostream& operator<<(std::ostream&, const Note&)`，让 `std::cout << note` 输出 ID、标题和状态。返回传入的流引用，以支持链式输出。格式化操作适合输出，不要在其中修改笔记状态。

运算符重载要保留调用者自然预期：相等比较应表达相等关系，`<<` 应表达输出。不要给笔记定义没有清楚数学或领域含义的 `+`、`-` 等操作。

### 2. 统一错误处理行为

至少演练以下情况，并确认集合状态正确：

- `show` 缺少 ID、ID 不是整数、ID 后带多余字符。
- `show` 或 `delete` 使用不存在的 ID。
- 删除第一条、最后一条、唯一一条笔记，以及空集合中的 ID。
- 输入未知命令或只有空白的命令行。
- 新增时输入空标题；选择是否允许空正文，并保持提示一致。

错误策略建议：

- 查找不到笔记：用 `std::optional` 的空值表达，这是正常业务结果。
- 删除是否成功：用 `bool` 表达，并给用户对应提示。
- 输入格式错误：在命令行层校验并提示用法，继续等待下一条命令。
- 内存分配失败等异常情况：让标准异常机制处理，或在程序最外层捕获并报告；不要用异常表示“ID 不存在”这种常见分支。

### 3. 比较异常与 C++20 错误结果类型

复习 `try` / `catch`、标准异常类型以及异常传播的基本规则。当前命令行输入通常可通过 `std::istringstream` 的状态检查处理，不需要为了每个解析失败都抛异常。

`std::expected<T, E>` 是 C++23 类型，不属于本项目的 C++20 基线。了解它解决的是“成功值或错误值”的显式返回问题即可；不要把它作为本阶段必需实现，也不要仅为使用它切换语言标准。当前以 `std::optional`、`bool` 和清晰的命令行校验覆盖需求。

### 当天验证

- 验证所有上述错误输入都能得到可理解的反馈，随后仍可继续使用程序。
- 对照 `Note` 的相等定义构造两个相等和两个不相等的对象。
- 若实现 `operator<<`，在 `std::cout << note << '\n';` 中使用并检查输出。
- 能说明为什么缺失记录不应当被当作异常，以及何时异常更合适。

## 建议的接口收敛

完成后，核心接口可接近以下形状；具体命名和返回类型由你根据实际实现决定：

```cpp
class NoteStore {
public:
    long add(std::string title, std::string content);
    std::optional<Note> find(long id) const;
    std::optional<Note> find(std::string_view title) const;
    bool erase(long id);
    const std::vector<Note>& all() const;
};
```

如果用 `std::string_view`，加入 `<string_view>`；使用 `std::span` 时加入 `<span>`；使用默认相等运算符无需额外头文件。接口仅作为方向，不要求机械照抄。
