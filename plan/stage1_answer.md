# 阶段 1：问题与答案

本文回答 `src/main.cpp` 中标注的两个 `why`，以及 `stage1.md` 中“第一天结束时应能回答”的四个问题。

## 代码中的两个 why

### 1. 为什么 `add()` 中要对 `title` 使用 `std::move`？

`title` 是 `add()` 的按值参数，因此函数里有一份自己的 `std::string` 对象。将它放进 `Note` 时，若直接写 `.title = title`，会从参数复制字符串内容到 `Note::title`。写成 `.title = std::move(title)` 则表示这个局部参数之后不再需要，允许 `std::string` 的移动赋值/构造接管其资源，通常可以避免复制动态分配的字符缓冲区。

`std::move` 本身不搬运任何数据；它只是把表达式转换成可移动的右值形式，让所选中的操作有机会执行移动。移动后，`title` 仍是一个有效对象，可以销毁或重新赋值，但不要依赖它原先的字符串内容。对短字符串，标准库实现可能使用小字符串优化，实际操作未必比复制更快；这里使用 `std::move` 的主要理由是表达“把这份局部值交给新笔记”。使用它需要包含 `<utility>`。

### 2. 为什么 `all()` 使用 `[[nodiscard]]` 并返回引用？

这两个设计各自解决不同问题：

- **返回 `const std::vector<Note>&`：** 以只读借用的方式提供内部集合，避免复制整个 vector 及其中所有笔记。`const` 表示调用者不能通过这个引用修改 vector 或其中的笔记。引用不拥有集合，不能在 `NoteStore` 销毁后继续使用；若集合发生结构性修改，也要留意已有迭代器、引用和指针可能失效。
- **标记 `[[nodiscard]]`：** 提醒调用者不要无意中丢弃 `all()` 的返回值，例如单独写 `store.all();` 却没有遍历或保存结果。编译器通常会对此给出警告。它只是诊断提示，不会改变运行时行为，也不强制编译失败。

注意：返回引用仅避免“返回时复制”。若调用者将结果赋给一个按值的变量，仍然会发生复制；想保持借用，应使用 `const auto& notes = store.all();`，或直接遍历返回值。

## `stage1.md`：第一天结束时应能回答

### 1. 为什么 `std::vector<Note>` 可以直接保存对象，而不必保存 `Note*`？

`std::vector<T>` 的用途之一就是连续保存一组 `T` 对象。这里的 `Note` 成员本身是 `int` 和 `std::string`，可以正常复制、移动和销毁，因此 vector 能直接管理每个 `Note` 的生命周期；vector 扩容时也会按类型规则搬迁或复制元素，销毁时会逐个销毁元素。`std::string` 又会自动管理自己的字符资源。

使用 `std::vector<Note*>` 并不会让笔记自动获得更好的管理：它只保存地址，仍需决定对象在哪里创建、由谁释放以及如何避免悬空指针。除非确实需要多态、稳定对象地址或独立所有权等设计，当前阶段直接按值保存更简单、更安全。

### 2. `const std::vector<Note>&` 表达了什么？调用者可以做什么、不能做什么？

它表示函数返回一个**指向既有 vector 的常量引用**：不创建 vector 副本，不转移所有权，调用者只能经由这个引用读取集合。调用者可以遍历、读取大小、读取笔记字段；不能通过此引用添加或删除元素，也不能修改元素字段。它不保证底层集合永远不变——拥有该集合的 `NoteStore` 仍可能通过其他非 const 操作改变它。

引用有效期受原对象约束：`NoteStore` 销毁后不能再使用此引用。若 `NoteStore` 改动 vector，之前取得的迭代器、元素引用或指针还可能失效。因此把它作为短期只读访问接口使用，不要长期缓存借用。

### 3. `Note` 中的 `std::string` 由谁负责释放内存？没有手写析构函数为什么仍能正常工作？

每个 `std::string` 对象负责管理自己的字符存储，并在自身生命周期结束时自动释放所需资源。`Note` 的生命周期结束时，其成员会自动按构造的逆序销毁；其中的字符串成员也随之析构并清理资源。`std::vector<Note>` 销毁元素时同样会触发这一过程。

因此，`Note` 不必自己手动分配或释放字符串缓冲区，也通常不需要自定义析构函数。这是 RAII 的典型应用：资源由对象的生命周期管理。成员都遵循正确的值语义时，优先采用 Rule of Zero，让编译器生成合适的析构、复制和移动操作。

### 4. 新笔记插入 vector 后，扩容可能对已有引用或指针造成什么影响？

若 `push_back` 导致 vector 扩容，vector 通常会申请新的连续存储，并把元素搬到新位置；旧存储中的元素地址不再有效。因此指向 vector 元素的指针、引用和迭代器都可能悬空，继续解引用会造成未定义行为。即使没有扩容，在 vector 中间插入或删除也可能使插入/删除位置及其后的元素引用、指针或迭代器失效。

对当前练习，新增或删除后重新查找所需笔记，不要长期保存元素地址。需要更稳定的引用时，应先根据具体需求选择合适容器或间接存储设计，而不是假设 vector 元素地址固定。
