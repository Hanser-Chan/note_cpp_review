# C++20 复习项目计划

## 项目方向：构建一个命令行个人知识库

建议做一个本地运行的命令行知识库（暂名 `cpp20_lab`）：用户可以添加、搜索、标记和归档笔记，数据保存在本地文件中。后续逐步加入标签、过滤、统计、导入导出、并发索引和自动化测试。

这个项目适合从头复习，因为它先有明确且小的可运行目标，之后每项需求都能自然引出一组 C++ 技能。最终项目仍保持命令行和本地文件范围，不需要先搭建服务端、图形界面或依赖复杂外部系统。

## 学习方式

- 以 C++20 为基准，使用标准库优先；遇到平台差异时明确记录，不把编译器扩展当成语言特性。
- 每天安排约 45–90 分钟：读一个主题、实现一个小功能、编译运行、写下当天遇到的语言问题。
- 每个阶段先保留能工作的版本，再逐步重构；不要一次把后续架构全部预制出来。
- 每个功能都通过程序行为验证。涉及文件格式、错误输入和并发的阶段，补上相应测试或可重复的演示。
- 学习时重点追问对象的生命周期、所有权、异常安全、接口边界和线程安全，而不只记语法。
- 第一天先确认本机工具链支持 C++20，并记录编译器及版本。建议使用 GCC、Clang 或 MSVC 的近期版本；首个程序验证 `-std=c++20` 或对应的 MSVC `/std:c++20` 选项。

## 阶段路线

### 阶段 0：工具链与最小程序（第 1 天）

**实现：** 创建程序入口，打印版本信息，并解析一个简单命令（例如 `help`）。

**复习：** 编译与链接的区别、头文件与源文件、命名空间、基本类型、函数、`const`、`auto`、作用域。

**产出：** 可从终端运行的程序；记录编译器、标准库和构建命令。

### 阶段 1：数据建模与值语义（第 2–3 天）

**实现：** 定义 `Note`，支持创建、展示和内存中的增删查。

**复习：** `struct` / `class`、访问控制、构造函数、成员初始化列表、`enum class`、引用、指针基础、`std::string`、`std::vector`、`std::optional`、值传递与引用传递。

**产出：** 一个内存中的笔记集合；能解释对象何时创建、复制、移动和销毁。

### 阶段 2：接口、重载与错误处理（第 4–5 天）

**实现：** 支持按 ID 查找和删除；为 `Note` 提供合适的比较或格式化操作；对无效命令和缺失记录给出清晰反馈。

**复习：** 函数重载、运算符重载的边界、`std::string_view`、`std::span`（适用时）、异常与错误返回的取舍、`std::expected`（若工具链支持；它属于 C++23，不作为本项目的 C++20 依赖）。

**产出：** 稳定的领域接口；明确哪些失败使用返回值表达，哪些情况才抛异常。避免为了练习而重载 `+` 等不符合类型语义的运算符。

### 阶段 3：STL 与算法（第 6–8 天）

**实现：** 标题搜索、标签过滤、排序、去重和统计；选择合适的容器保存标签或索引。

**复习：** `std::vector`、`std::array`、`std::map` / `std::unordered_map`、`std::set`、迭代器、范围 `for`、标准算法、lambda、谓词、结构化绑定、`<ranges>` 的基础视图。

**产出：** 一组可演示的搜索与统计命令；能说明容器选择、复杂度和迭代器失效风险。

### 阶段 4：资源管理与指针（第 9–10 天）

**实现：** 将解析、存储和命令处理拆成独立模块；明确每个组件的所有权和生命周期。

**复习：** RAII、析构函数、拷贝/移动构造与赋值、Rule of Zero / Three / Five、`std::unique_ptr`、`std::shared_ptr`、`std::weak_ptr`、裸指针和引用的非拥有语义、`std::filesystem`。

**产出：** 资源由明确的对象负责；默认优先 Rule of Zero 和值语义，仅在确有动态多态或共享所有权需求时使用智能指针。

### 阶段 5：持久化与稳健性（第 11–13 天）

**实现：** 保存和加载笔记，处理文件不存在、损坏数据、权限或写入失败；支持安全地覆盖保存。

**复习：** 文件流、二进制与文本格式取舍、解析与校验、异常安全保证、`std::filesystem`、头文件组织、前置声明和编译依赖。

**产出：** 重启后数据仍存在；对无效输入和 I/O 失败有可理解的错误信息。先定义简单、带版本号的文本格式，不急于引入第三方序列化库。

### 阶段 6：泛型与现代 C++（第 14–16 天）

**实现：** 抽取可复用的过滤或结果格式化逻辑；按需加入一个泛型组件。

**复习：** 函数模板、类模板、模板参数推导、`constexpr`、`if constexpr`、概念 `concept`、`requires`、`std::variant`、`std::visit`、`std::variant` 与继承多态的适用场景。

**产出：** 少量有实际用途的模板代码；能读懂常见模板报错。避免为了展示模板而把简单逻辑过度泛化。

### 阶段 7：CMake 与测试（第 17–19 天）

**实现：** 使用 CMake 管理多个源文件，配置 C++20，拆分核心库、命令行程序和测试目标；加入 CTest。

**复习：** `CMakeLists.txt`、target 思维、`target_compile_features`、`target_include_directories`、Debug/Release 构建、生成器、依赖传播、CTest。测试库可先用简单自写断言，之后按需要选 Catch2 或 GoogleTest。

**产出：** 能从干净构建目录配置、编译和运行测试；编译选项作用于目标而不是全局污染项目。

### 阶段 8：线程与并发索引（第 20–22 天）

**实现：** 为较大的笔记集合建立后台搜索索引或统计任务；提供等待或取消策略，确保程序退出时任务安全结束。

**复习：** `std::thread`、`std::jthread`、`std::mutex`、`std::lock_guard` / `std::scoped_lock`、条件变量、原子类型、数据竞争、死锁、同步与异步的边界，以及 `std::future` / `std::async`。

**产出：** 一个可重复验证的并发功能；说明共享状态、锁的保护范围和线程退出规则。若任务很短或数据量很小，可以保留串行实现，并把并发功能做成独立实验，避免无意义地复杂化主流程。

### 阶段 9：收尾与回顾（第 23–24 天）

**实现：** 完善帮助信息、参数校验、示例数据和 README；从干净目录完整构建并演示核心路径。

**复习：** API 设计、模块边界、性能测量基础、编译器警告、调试器和 sanitizer（工具链支持时）、代码审查。

**产出：** 一个别人能构建并使用的小项目；整理“仍不熟悉的 10 个问题”和下一轮计划。

## 建议的目录演进

不要第一天就创建所有目录，随着阶段推进再拆分：

```text
cpp20_lab/
  CMakeLists.txt
  README.md
  include/
    cpp20_lab/
  src/
  tests/
  data/
```

前期可以只用 `main.cpp`。当模型、存储、命令行逻辑开始互相干扰时，再逐步拆成对应模块。

## 贯穿项目的 C++ 检查清单

- 这个对象是谁创建、谁拥有、何时销毁？
- 这里需要复制、移动、借用，还是共享所有权？
- 容器修改后，已有迭代器、引用或指针是否仍有效？
- 错误是通过返回值还是异常表达？调用方能否正确处理？
- 新抽象是否让调用更简单，还是只增加模板和类型？
- 并发代码中，哪些数据被共享，谁负责同步？能否改成不可变数据或消息传递？
- 功能是否能在干净构建后复现？

## 范围与完成标准

完成计划时，项目应能通过 CMake 以 C++20 构建，提供基本命令行笔记操作，支持本地持久化、搜索和标签过滤，包含可重复运行的测试，并有一个适度且安全的并发实验。更重要的是，能够解释代码中主要的所有权、生命周期、容器选择、构建目标和同步决策。

这条路线有意覆盖最常用的 C++20 日常能力，不以“记住全部标准库”为目标。模块、协程、网络库、复杂模板元编程和第三方框架可放到后续专题；需要时再从项目需求引入。
