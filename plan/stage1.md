# 阶段 1：数据建模与值语义

本阶段对应总计划中的“阶段 1：数据建模与值语义”（第 2–3 天）。默认阶段 0 的命令行程序已经能在本机以 C++20 编译运行。本阶段先把程序扩展为一个纯内存的笔记管理器，不加入文件持久化、CMake 或复杂命令解析。

## 阶段目标

完成后，程序应能在一次运行中创建笔记、列出笔记、按 ID 查看笔记，并按 ID 删除笔记。数据存放在内存中，程序退出后丢失是预期行为。

通过实现这些行为复习：

- `struct` 与 `class`、访问控制、构造函数、成员初始化列表和 `enum class`
- `std::string`、`std::vector`、`std::optional`
- 值传递、常量引用、引用和指针的基础语义
- 对象的创建、复制、移动和销毁时机
- 函数如何表达成功、缺失结果和输入错误

预计用时：两天，每天约 45–90 分钟。若某个主题需要更多时间，可以延长阶段，不必为了日期赶进度。

## 约定与范围

- 延续阶段 0 已经建立的构建方式和目录，不要为这阶段提前引入 CMake。
- 如果当前程序还没有命令分派，可以先用固定示例数据演示接口，随后再接最简单的终端命令。
- `Note` 暂时只保存 `id`、`title`、`content` 和状态；标签、日期、归档、搜索过滤都留到后续阶段。
- 笔记由 `std::vector<Note>` 按值保存。此时不需要 `new` / `delete`、裸指针拥有资源，也不需要智能指针。
- ID 在本次运行内唯一即可；可用递增整数。暂时不处理持久化后的 ID 冲突。
- 缺失笔记属于正常业务结果，用 `std::optional` 表达；无效用户输入给出清晰提示，不让程序崩溃。

## 建议的数据模型

```cpp
#include <string>

enum class NoteStatus {
    active,
    archived,
};

struct Note {
    int id;
    std::string title;
    std::string content;
    NoteStatus status{NoteStatus::active};
};
```

起步时可以用 `struct` 让資料保持簡单直接。若后面需要限制非法状态或集中维护不变量，再考虑把成员设为 `private` 并通过构造函数和成员函数保护它们。不要为了“面向对象”而一开始就给每个字段增加 getter/setter。

建议的最小接口：

```cpp
class NoteStore {
public:
    int add(std::string title, std::string content);
    const Note* find(int id) const;
    bool erase(int id);
    const std::vector<Note>& all() const;

private:
    int next_id_{1};
    std::vector<Note> notes_;
};
```

接口可以随实现调整。这里的 `const Note*` 是借用指针：`NoteStore` 仍拥有笔记，调用者只在安全的时间范围内读取它。需要解释返回指针何时失效；`std::vector` 增长可能使元素地址失效，因此不要长期保存这个指针，也不要在 `add`、`erase` 后继续使用旧指针。若当前更愿意避免指针，可先写 `std::optional<Note>` 返回副本，随后比较两种接口的语义和代价。

## 第一天：建模并完成内存中的新增与列出

### 1. 复查阶段 0 的程序

- 确认程序仍使用 C++20 编译。
- 找到入口函数、命名空间、函数声明和定义。
- 回忆编译器如何把源文件编译并链接为可执行程序。

### 2. 定义 `Note` 和状态

- 创建 `NoteStatus`，使用 `enum class` 表示 active / archived 状态。
- 创建 `Note`，包含整数 ID、标题、正文和状态。
- 让状态有明确的默认值；确认字符串默认构造后为空。
- 写一个展示函数，按固定格式输出字段和状态。

### 3. 实现 `NoteStore::add`

- `NoteStore` 持有 `std::vector<Note>` 和下一个 ID。
- 新增笔记时分配 ID，并将 `Note` 放入 vector。
- 返回分配的 ID，供命令行展示和后续查找。
- 使用初始化列表或聚合初始化构造对象；观察字符串是复制还是移动进入容器。

### 4. 实现列出功能

- `all()` 以只读方式暴露笔记集合，或提供一个遍历打印的成员函数。
- 空集合时输出明确提示。
- 非空时逐条打印 ID、标题和状态；正文可在查看单条笔记时再完整显示。

### 5. 当日验证

- 启动程序，新增至少两条笔记并列出。
- 确认 ID 不重复且按预期递增。
- 确认默认状态是 active。
- 用含空格的标题和正文，观察输入处理是否符合预期；如果当前命令输入方式不支持，可先从代码中的测试数据验证，并记录限制。

**当天结束时应能回答：**

1. 为什么 `std::vector<Note>` 可以直接保存对象，而不必保存 `Note*`？
2. `const std::vector<Note>&` 返回值表达了什么？调用者可以做什么、不能做什么？
3. `Note` 中的 `std::string` 由谁负责释放内存？如果没有手写析构函数，为什么仍能正常工作？
4. 新笔记插入 vector 后，vector 扩容可能对已有引用或指针造成什么影响？

## 第二天：查找、删除与对象生命周期

### 1. 实现按 ID 查找

- 遍历 vector 查找匹配 ID 的笔记。
- 对成功结果返回只读借用（例如 `const Note*`）；找不到时返回 `nullptr`。
- 若要统一使用标准库的显式可选结果，也可以返回 `std::optional<Note>`。注意这会返回一份值副本，而不是容器中对象的引用。
- 在调用端先检查结果，再读取内容；不得解引用空指针。

### 2. 实现删除

- 找到匹配 ID 的元素。
- 找到则使用 `vector::erase` 删除并返回 `true`；不存在则返回 `false`。
- 删除后重新查询并列出，确认容器状态正确。
- 讨论删除对迭代器、引用和指针的影响；删除位置及其后的 vector 元素可能发生移动，相关借用不能继续使用。

### 3. 加入最简单的命令交互

推荐命令：

```text
add <title>       新增一条标题为 title 的笔记（正文可先使用固定内容或后续提示输入）
list              列出全部笔记
show <id>         查看一条笔记
delete <id>       删除一条笔记
help              显示用法
quit              退出
```

命令解析保持简单，不追求通用 CLI 框架。若解析标题和正文影响本阶段的数据建模学习，先通过函数调用演示 CRUD，再把交互细节留到后面。

### 4. 观察值语义

可以临时在局部代码中做如下小实验，观察对象何时复制或移动：

```cpp
Note original{1, "C++20", "Review value semantics"};
Note copied = original;
Note moved = std::move(copied);
```

实验后回答：

- `original`、`copied` 和 `moved` 是三个独立对象吗？
- 移动后 `copied` 还能否销毁或重新赋值？（能；但不要依赖其字符串内容，除非类型明确保证。）
- 为什么 `Note` 通常不需要自己编写拷贝、移动构造函数和析构函数？
- 哪些场景传 `const T&` 能避免复制？什么时候按值传递反而更合适？

## 完成检查

逐项确认：

- [ ] `Note` 与 `NoteStatus` 能表达当前领域数据，默认状态明确。
